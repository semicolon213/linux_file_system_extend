# ADR-0003 이벤트 정규화·병합·유실 정책

상태: 제안 (2026-11-24, ARCH-001). 수치는 측정 전 가정이며 G8 결과로 조정한다.

## 결정
1. 이동 짝 맞추기: cookie 대기 표, 시간창 50ms. 짝이 맞으면 RENAME(같은 부모)/MOVE, 아니면 MOVED_OUT/MOVED_IN.
2. 병합(MON-027): 한 전달 배치(최대 16ms 또는 256개) 안에서 같은 (kind, path)의 MODIFY끼리, ATTRIB끼리만, 사이에 같은 경로의 다른 kind가 없을 때만. 순서를 바꾸는 병합은 없다.
3. 유실: 커널 overflow와 전달 큐 포화(8192)를 같은 gap으로 처리한다. OVERFLOW → 재탐색 → RESYNC_DONE. 조용히 버리지 않는다. mon은 파일 스냅샷을 갖지 않고 소비자가 다시 읽는다.
4. 재귀 감시는 심볼릭 링크를 따라가지 않고 마운트 경계(st_dev 변화)를 넘지 않는다. 동적 등록 직후 스캔으로 합성 CREATE를 만든다.
5. 겹치는 감시 루트(같음, 조상, 자손)는 등록을 거부한다. inotify는 같은 inode에 같은 wd를 돌려주므로 겹침을 허용하면 루트별 수명 관리가 복잡해진다.
6. 루트 MOVE_SELF는 새 경로를 알 수 없어 감시를 멈춘다(STOPPED).

## 대안
- 시간 기반 디바운스(같은 경로 N ms 묶기): 지연이 늘고 NFR-002(100ms) 여유가 줄어 버림.
- 큐 포화 시 생산자 블로킹: 커널 큐가 대신 넘쳐 결국 같은 유실이 생기고 원인이 가려짐.
- 겹치는 루트 허용 + wd refcount: 사용자 이득에 비해 구현·테스트 비용이 큼. 사용자 요구가 생기면 재검토(미결 U-3).

## 결과
테스트는 합성 overflow 주입(`fs_mon_testing.h`)과 작은 큐 용량으로 유실 경로를 재현한다. 실제 커널 overflow는 root 없이 재현하기 어려워 G8 부하 시험에서 관찰만 한다.
