# ADR-0009 이력 영속화: SQLite 단일 writer와 내용 주소 블롭 저장소

상태: 승인 (2026-11-25, Coordinator, R2 계약)

## 맥락
R2 데모 핵심은 외부에서 바뀐 파일의 직전 버전과 비교하고(HIS-007/008/009) 되돌리거나 삭제된 파일을 되살리는 것이다(HIS-011/012). inotify는 바뀐 뒤에 알리므로 바뀌기 전 내용은 미리 보관해 둬야 한다. 이벤트 기록은 재시작 뒤에도 남아야 하고(HIS-001), 강제 종료 뒤에도 DB가 깨지지 않아야 한다(NFR-014). 이벤트는 초당 1000건까지 오고(NFR-005) 메인 스레드와 inotify 스레드를 막으면 안 된다.

## 결정
1. 메타데이터는 SQLite 하나(`$XDG_DATA_HOME/filescope/history.db`, WAL, `synchronous=NORMAL`)에 둔다. 연결은 his 전용 스레드 하나만 쓴다(단일 writer). 메인 스레드는 명령 큐로 요청하고 결과는 `Glib::Dispatcher`로 받는다(ADR-0008). 외부 프로세스 경합은 busy_timeout 2초 + 트랜잭션 재시도 3회로 한정한다.
2. 파일 내용은 DB 밖 내용 주소 저장소(`blobs/<sha256>`)에 압축 없이 둔다. 같은 내용은 한 번만 저장한다. 블롭 파일을 먼저 fsync·rename하고 그 뒤 DB 행을 커밋한다. 커밋 뒤 참조가 0이 된 파일을 지운다. 그래서 끊기는 지점이 어디든 "행이 있으면 파일이 있다"가 성립하고, 남는 것은 열 때 지우는 orphan 파일뿐이다.
3. 버전은 쓰기 완료 이벤트(CLOSE_WRITE, 파일 이름으로 들어오는 RENAME·MOVE·MOVED_IN)가 경로별 300ms 조용해진 뒤 만든다. 감시 시작·재탐색·재개 때 작은 파일(1MiB 이하, 루트당 2만 개·128MiB)은 기준 스냅샷을 만든다. 캡처 중 크기·mtime이 바뀌면 한 번 다시 하고, 그래도 바뀌면 버린다(불완전 버전 없음).
4. 보관 한도: 경로별 20개, 파일 8MiB, 전체 512MiB, 이벤트 20만 행·30일. 각 경로의 최신 버전은 지우지 않는다. 수치는 측정 전 가정이다(E-11, E-12).
5. 민감 경로(.ssh, .gnupg, 키 파일 등)와 소음 경로(.git, node_modules, 편집기 임시 파일), 자기 데이터 디렉터리는 버전을 만들지 않는다. 데이터 디렉터리는 0700, 파일은 0600.
6. 복원은 his가 현재 내용을 PRE_RESTORE 버전으로 먼저 보관한 뒤 `fs::install_file`(같은 디렉터리 임시 파일 → fsync → rename, stamp 비교)로 쓴다. 사용자 파일 쓰기는 fs만 한다.
7. mon과 his는 서로 모르고 ui가 메인 스레드에서 이어 준다. his는 이벤트 배치의 `EventPtr`만 복사해 넘겨받는다.

## 대안
- 내용을 SQLite BLOB 열에 저장: 큰 BLOB이 WAL을 부풀리고 VACUUM 없이는 공간을 돌려받지 못한다. 블롭 하나 지울 때 DB 페이지 정리가 필요하다. 기각.
- 버전마다 파일 복사(중복 제거 없음): 저장 → 되돌림 → 다시 저장 같은 반복에서 같은 내용이 쌓인다. 해시는 GLib(`Glib::Checksum`)로 새 의존성 없이 된다. 기각.
- 압축·델타 저장(git pack 방식): 공간은 줄지만 구현과 복구 검증이 커진다. 데모 범위(8MiB 이하 텍스트·이미지)에는 이득이 작다. R3 이후로 미룸.
- mon watcher 스레드나 job worker에서 캡처: watcher가 파일을 읽으면 inotify 읽기가 밀려 overflow가 늘고, job worker는 긴 복사 뒤에 캡처가 밀린다. 전용 스레드로 기각.
- 여러 연결(읽기 전용 연결을 메인에): WAL이라 가능하지만 메인 스레드에서 디스크 I/O가 생기고 연결 수명 관리가 늘어난다. 조회도 his 스레드로 보내는 편이 단순하다. 기각.
- 기준 스냅샷 없이 첫 쓰기부터 보관: 첫 변경의 "바뀌기 전"이 없어 데모의 첫 Diff가 비게 된다. 기각. 반대로 모든 파일을 크기 제한 없이 기준 스냅샷: 큰 저장소에서 시작 비용과 공간이 감당되지 않는다. 한도를 두는 쪽을 택한다.
- reflink(FICLONE)로 복사 비용 절감: 파일 시스템마다 다르고(ext4 미지원) 대체 경로가 필요하다. 나중 최적화로 남긴다.

## 결과
- 새 의존성은 libsqlite3-dev 하나다(설치 확인 2026-11-25). his 모듈만 `sqlite3.h`를 쓴다(check-architecture.sh).
- 앱이 꺼져 있던 동안과 일시 정지·overflow 구간의 변경은 버전이 없다. gaps 테이블로 "이 사이 변경은 알 수 없음"을 보일 수 있다(E09 "스냅샷 없는 삭제는 복구 불가 명시").
- 하드 링크는 경로마다 따로 버전이 생긴다(E-7과 같은 성격).
- 검증: 강제 종료 후 integrity_check·불변식·orphan 정리(TESTING §8), 초당 1000 이벤트 기록 부하(G8).
