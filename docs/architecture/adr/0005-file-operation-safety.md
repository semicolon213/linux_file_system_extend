# ADR-0005 파일 작업 실행 방식과 안전 규칙

상태: 제안 (2026-11-24, ARCH-001)

## 결정
1. 단일 syscall 수준 작업(파일·폴더 생성, 이름 변경, 단일 휴지통, 텍스트 읽기·저장)은 동기 함수, 재귀·다중 항목 작업(복사, 이동, 일괄 휴지통, 영구 삭제)은 작업 큐. R1 대상은 로컬 파일 시스템이며 네트워크 파일 시스템(NAV-020, P3)의 지연은 고려하지 않는다.
2. 작업 큐 동시 실행 1개(FIFO). 같은 파일을 두 작업이 동시에 만지는 경쟁을 없앤다. 동시성 설정은 JOB-010(P1).
3. 충돌 정책은 제출 시 한 번 정한다(FAIL/SKIP/KEEP_BOTH/OVERWRITE). 작업 중 사용자에게 묻는 왕복은 R1에 없다. ui는 `fs_ops_find_conflicts`로 미리 물어보고 정책을 고른다.
4. 쓰기는 같은 디렉터리 임시 파일(`.filescope-XXXXXX`) → fsync → rename. 실패·취소 시 임시 파일 삭제. EXDEV 이동은 항목 복사 완료 후 원본 삭제.
5. 영구 삭제·덮어쓰기·강제 저장은 `FS_OPS_FLAG_CONFIRMED` 필수. 휴지통 미지원 시 자동으로 영구 삭제하지 않는다.
6. 복사는 심볼릭 링크를 링크로 복사하고, FIFO·장치·소켓은 항목 실패(NOT_SUPPORTED). 권한 비트와 mtime을 보존하고 소유자는 보존하지 않는다.
7. 잘라내기·붙여넣기 클립보드는 앱 내부 상태다(시스템 클립보드 연동은 미결 U-7).

## 대안
- 모든 작업을 큐로: 긴 복사 중 새 폴더 만들기가 대기하게 된다.
- 작업 중 충돌 질문: worker가 main 응답을 기다리는 동기화가 필요하고 종료 경쟁이 늘어난다.

## 결과
텍스트 편집(FS-005)은 stamp(dev, ino, size, mtime_ns) 비교로 외부 수정 충돌을 잡는다(E07).
