# 개발 워크플로우
BACKLOG → READY → IN_PROGRESS → VERIFY → QA → APPROVED → MERGED. 실패 시 REWORK, 선행 조건 부족 시 BLOCKED.
1. Coordinator가 기능 ID와 계약, 허용 파일, 테스트를 지정한다.
2. 구현자는 기준 커밋과 테스트 결과를 기록하고 전용 worktree에서 작업한다.
3. 구현 후 자동 검사와 handoff를 제출한다.
4. QA는 동일 커밋을 독립 검증한다. FAIL이면 재현 근거와 함께 반환한다.
5. Integration은 승인된 SHA만 통합하고 전체 회귀 검사를 수행한다.
6. 통합 성공 후 TRACEABILITY와 PROGRESS를 갱신한다.
QA 이후 코드 변경 시 기존 승인은 무효다. 작업 상태는 Coordinator만 확정한다.

## UI/UX 디자인 권한
- 시각 디자인은 사용자가 Impeccable을 통해 별도로 제작한다. 에이전트는 색상, 타이포그래피, 간격, 레이아웃, 아이콘, 애니메이션, 테마 및 디자인 시스템을 임의로 정의하거나 변경하지 않는다.
- UI 기능 요구사항, 접근성, 상태 전달, GTK 바인딩 및 동작 테스트는 유지한다. 디자인 미제공 시 화면 스타일을 확정하지 말고 기능 로직과 인터페이스를 구현한다.
- 사용자가 제공한 디자인을 승인된 기준으로 적용하며 변경이 필요하면 먼저 승인을 요청한다. QA는 기능과 접근성을 검증하고 시각 디자인을 직접 수정하지 않는다.
